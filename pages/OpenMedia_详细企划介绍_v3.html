01 / Vision

不是“另一个豆瓣”，而是中文世界的开放文化层。

真正的差异化不在视觉翻新，而在制度设计：开放数据、开放迁移、透明修订、平权评分、受控 AI 接入，以及不依赖重广告和上瘾式推荐的商业结构。

Open Ownership

用户不是平台的数据资产

评分、收藏、标签、评论和个人档案可以完整导出。迁入与迁出拥有同等重要性，开放不是获客技巧，而是产品承诺。

Equal Voice

权限可以分层，意见不能分级

高信誉用户拥有更低操作摩擦和更高治理权限，但任何通过真实性检查的评分都保持一人一票。

Sustainable Incentive

收入与用户利益同方向

用户为高级工具、AI、API 和可靠服务付费，而不是为更高曝光、评分权重或更强社区话语权付费。

开放知识，用户拥有数据；信誉约束行为，观点保持平等；AI 提升效率，商业反哺社区。
这是 OpenMedia 的制度性底线。任何未来功能都应以这三条原则作为产品评审标准。
02 / Product Model

知识层与社区层，从一开始就解耦。

OpenMedia 的长期资产不是某一批页面，而是持续增长的文化知识图谱。社区负责产生判断、评论和修订；知识层负责稳定表达作品、版本、人物和关系。

统一管理 Work、Edition、Release、Person、Organization、Credit、External ID、Tag、Relation 与 Revision。尤其强调“作品”与“具体版本”的区分。

03 / Architecture

协议优先，分层单体起步。

早期不为“技术先进感”过度微服务化。优先保证数据模型正确、接口稳定、修订可追踪，并预留后续拆分空间。

Layer 01
OpenMedia Graph
PostgreSQL 作为主数据库，承载作品、版本、人物、组织、关系与 Revision。JSONB 用于扩展字段，pgvector 可承载早期语义检索。
核心资产层
Layer 02
Domain Services
Identity、Knowledge、Community、Trust、Moderation、Integration 六个领域模块。初期可以保持模块化单体，增长后再按负载拆分。
业务逻辑层
Layer 03
Open Protocol
REST / OpenAPI、JSON-LD、OpenMedia Import / Export Schema、MCP。所有人类客户端、第三方应用与 Agent 都通过受控接口访问底层能力。
开放协议层
Layer 04
Experience
Web 优先，推荐 Next.js + TypeScript。条目页与搜索页兼顾 SSR / SEO；评分、收藏、评论和 Wiki 编辑采用交互式客户端能力。
产品体验层
04 / Data & Backend

数据库结构必须从第一天可演化。

真正复杂的不是“存一个电影条目”，而是实体消歧、版本关系、字段级修订、来源追踪、跨站 ID 对齐和未来 AI/搜索能力对数据结构的要求。

Core Data

05 / Trust & Governance

信誉系统控制破坏力，不制造文化等级。

开放社区真正需要解决的是 Sybil Attack、Spam、脚本 Bot、恶意编辑与评分操纵。信誉系统的目标是判断“这个行为是否可信”，而不是判断“这个人的审美是否更正确”。

信誉影响什么

每日评论 / 评分 / 编辑额度
Wiki 修改是否需要人工审核
是否允许外链、批量编辑、回滚、合并
举报与 Revision 的可信度
异常行为触发阈值与风控强度

信誉绝不影响什么

单次评分的票权
评论观点是否“高级”
付费会员是否更容易被看见
主流观点是否拥有制度性优势
领域编辑是否拥有更高审美权重
核心原则：Trust controls capability, not opinion. 信誉决定你能做什么，不决定你的观点值几票。
06 / AI Infrastructure

AI 负责效率，人类保留最终判断。

AI 被设计为基础设施：承担低成本审核、搜索增强、实体消歧和 Wiki 辅助；复杂争议、价值边界和最终处罚仍由人类与明确规则决定。

Moderation

分层模型审核

低成本模型处理 Spam 和简单分类；中等模型处理语义判断与 Wiki 冲突；大模型仅用于复杂仲裁辅助和深度实体消歧。

Wiki Copilot

AI 只提案，不越权

发现重复条目、人物别名、ISBN/外部 ID 冲突和版本关系问题，并生成 Proposal 进入正常 Revision 流程。

Personal Agent

用户自己的文化 Agent

在明确授权后读取个人收藏、评分、标签和评论，用于口味分析、年度回顾、自然语言检索和跨媒介推荐。

07 / Open Access

不仅开放给人，也开放给 Agent。

平台从协议层支持开放使用，而不是把 AI 绑定在自家聊天框中。不同主体通过 Scope 获取最小必要权限。

Import / Export

统一开放档案格式

OpenMedia Archive 支持 JSON / CSV。官方只定义格式与导入器，不把官方爬虫作为迁移核心能力。

REST / OpenAPI

第三方应用可直接接入

基础知识查询开放；更高 QPS、批量同步、语义检索、实体消歧与 SLA 可成为商业能力。

MCP

AI Agent 原生接口

支持 library:read、rating:write、list:write、wiki:propose 等细粒度 Scope，普通 Agent 不直接获得高风险写权限。

09 / Sustainable Business

先自我供血，再扩大商业价值。

商业化的目标不是尽可能把用户变现，而是让平台在不牺牲社区原则的情况下持续存在。最优收入结构应尽量降低对广告和停留时长的依赖。

Human Signal

授权的人类文化判断数据

长期最稀缺的资产可能是可证明为真人产生、权利链清晰、带 Trust 与 Provenance 的高质量评论和行为数据。

10 / Data Licensing

开放，不等于免费掠夺。

平台可以商业化高质量真人数据，但应采用明确授权、可撤销、可审计的许可机制，而不是在用户协议中做无限制的笼统授权。

Open Knowledge

第一层：公共知识

作品、人物、版本、关系与 External IDs 尽可能开放，构成 OpenMedia 的公共文化底座。

Aggregate

第二层：社区聚合数据

评分分布、时间趋势、标签趋势和匿名观点聚类可以作为 API、研究与商业分析服务。

Licensed Human Signal

第三层：明确授权的真人数据

评论、评分、Human Provenance、Trust、Spam Confidence 与社区 Rewards 形成高价值数据资产，但必须拥有清晰许可链。

11 / Roadmap

先做可信社区，再做开放生态。

项目不追求一开始覆盖所有条目与所有用户，而是先形成高文化密度、高贡献率的种子社区，建立制度与数据质量，再逐步打开协议与商业能力。

Phase 01

Alpha

Work / Person / Edition / Release、Search、Rating、Collection、Review、Wiki、Revision、Import / Export、Trust v1。

Phase 02

Seed Community

聚焦电影、阅读与独立音乐种子用户，培养领域编辑者，形成稳定 Wiki 与评论循环。

Phase 03

Open Ecosystem

开放 REST / OpenAPI、MCP、JSON-LD、社区转换器、个人文化 Agent 和 Pro 能力。

Phase 04

Sustainable Growth

会员、B2B API、数据服务与联盟收入完成自我供血，再扩大产品和团队。

12 / Risk

最大的风险不在开发，而在冷启动与制度执行。

技术可做并不等于社区可成。项目应从第一版就对数据来源、社区污染、商业异化和合规成本做制度性预防。

Risk 01

冷启动

不要做“百万空条目”。先追求高质量贡献者和真实互动密度。

Risk 02

数据来源

不把大规模复制第三方商业数据库当作核心冷启动策略。

Risk 03

Spam / Bot

通过 WAF、Rate Limit、行为风控、AI 审核、信誉分层与人工仲裁共同处理。

Risk 04

商业异化

如果收入最终主要依赖广告和停留时长，平台会重新长成传统内容平台。

OpenMedia 的长期价值，不只是一个“书影音社区”，而是一层可开放调用、可持续积累、可以被用户带走的文化基础设施。

它通过 Wiki 机制维护公共知识，通过平权评分和透明信誉机制维持社区，通过 Import / Export、REST、OpenAPI、MCP 和 JSON-LD 连接外部世界，并通过会员、API、AI 服务和明确授权的人类信息数据产品形成长期商业闭环。
